# dsh-native-app

Five DSH tools for macOS application development: `native_project`, `native_check`, `native_inspect`, `native_input`, and `native_stop`. The plugin supplies XcodeGen/Xcode build and a targeted window observation chain; it contains no game engine or task-specific implementation.

Use `native_project` once, add a small behavior, then `native_check`. Read the returned PNG with `read_image`. Use `native_input` and read its new capture to check an interaction. Only then record a working increment. `native_inspect` can list windows or capture again. `native_stop` quits only the tracked PID and process generation.

Xcode build logs and PNGs live under `workspace/native-output/`; structured receipts and managed process state live in `control/native/`. The workspace must ignore `native-output/` and `build/` in Git. Each receipt records the source revision, built product, PID/generation, window ID and image hash. An interaction receipt proves dispatch and capture, not the expected visual effect.

The pinned Peekaboo 4.6.0 CLI performs app/window inventory and input. `screencapture -l` writes the selected window into the workspace. Peekaboo 4.6.0 deliberately stores snapshots and its mutation journal under the account's physical `~/.peekaboo`; `see` and UI mutation fail inside DSH `workspace-write`, even with `PEEKABOO_CONFIG_DIR`. Therefore the plugin uses an explicit host-side `execFile` capability **only for fixed Peekaboo UI mutation commands**. The default click uses a fresh exact-window `see` receipt followed by a background accessibility click. For a custom-drawn surface such as `MTKView`, `native_input` also accepts `delivery: "synthetic"`: it focuses the managed window if needed, verifies that the managed app and window are frontmost, translates window-relative coordinates to display coordinates, then dispatches a synthetic click. The returned capture remains evidence of the effect; `effectVerified` stays false until the model inspects it. Key holds and mouse moves use the selected PID/window and foreground dispatch. All candidate builds, launches, captures and app inventory still use `ctx.shell` with DSH sandbox policy. The plugin never calls Peekaboo's agent or AI analysis. Peekaboo's exact-window capture is not used for durable evidence because its internal snapshots sit outside the workspace; `screencapture -l` produces the receipted PNG instead.

Process provenance is a new PID/start identity and bundle ID after `open -n -F`. The sandbox denies `/bin/ps`, so executable-path observation remains unavailable in V1; the built product path is retained, but is not claimed as an independently observed process path. `native_stop` rechecks PID/start identity and asks Peekaboo to quit exactly that generation.
